# Ontology-Constrained Verification and Shadow Mode

## 1. Objective and Theoretical Basis

In high-stakes civil and hydraulic engineering domains, factual hallucinations regarding quantitative parameters (such as dam crest levels, dead storage elevations, or maximum spillway capacities) pose significant operational hazards. 

The ontology verification subsystem in VietIrr-RAG investigates whether symbolic domain knowledge and formal constraint checking can be combined with neural LLM generation to detect and audit factual claims.

## 2. Technical Claim Schema

Each assertion generated by the LLM is processed by an atomic claim extractor into a structured representation:

```text
TechnicalClaim = {
    entity:           "Hồ Thác La",
    parameter:        "diện tích đáp ứng",
    value:            342.0,
    unit:             "ha",
    temporal_context: "tháng 06/2019",
    evidence_id:      "TAB_IRR_CTL_2019_1fc21515_P0003_02_R002_C003"
}
```

## 3. Domain Constraints Registry

The repository formalizes 45 domain constraints in OWL/TTL (`ontology/constraints_v0_1.ttl`) and JSON schema (`ontology/domain_constraints_v0_1.json`), covering:
- **Elevation Hierarchy**: $MNC \le MNDBT \le MNLKT \le CaoTrinhDinhDam$ (Dead water level $\le$ Normal water level $\le$ Design flood level $\le$ Dam crest elevation).
- **Physical Bounds**: Capacity volume (million m³), discharge rates (m³/s), irrigated area (ha).
- **Temporal Consistency**: Dates and operational timeframes within legal decision applicability.

## 4. Evidence Matching & Verification Verdicts

Extracted claims are cross-checked against retrieved source evidence units:
- **SUPPORTED**: Both the entity-parameter binding and the quantitative value strictly match the source text or table cell.
- **CONTRADICTED**: The value or parameter conflicts with the underlying document facts.
- **UNKNOWN**: The claim cannot be definitively derived from the retrieved evidence.

## 5. Shadow Mode Integration

During research ablations (A0 to A3), enforcing hard rejection (blocking answers when verification fails) resulted in an unacceptable false rejection rate of 8.3% due to natural language paraphrasing and grammatical complexity.

Consequently, the active production pipeline integrates ontology verification in **Shadow Mode**:
- Generation is never blocked or altered in real time.
- Claim extraction and constraint validation execute asynchronously in the background.
- Telemetry metrics (supported claims, contradiction signals, parameter bindings) are logged for offline diagnostic analysis and system evaluation.

## 6. Current Limitations

- **Extraction Recall**: Complex sentences with multiple clauses may yield incomplete atomic claim tuples.
- **Advisory Only**: Shadow Mode serves as an experimental observability tool rather than a certified safety guarantee.
